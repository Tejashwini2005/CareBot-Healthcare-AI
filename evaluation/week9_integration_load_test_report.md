
# CareBot Healthcare AI — Week 9 Report
## Integration and Testing

### 1. Objective
The objective of Week 9 was to integrate the trained machine-learning model into an API, perform integration testing, and evaluate API performance under 50 concurrent requests.

### 2. Technology Stack
- Python 3.11
- FastAPI
- Scikit-learn
- Joblib
- Pandas
- Pytest
- HTTPX
- Uvicorn

### 3. Model Integration
The tuned model, `models/best_model.joblib`, was integrated into the FastAPI application in `app.py`.

The API provides the following endpoints:

| Endpoint | Method | Purpose |
|---|---|---|
| `/health` | GET | Checks API health and model loading status |
| `/predict` | POST | Accepts validated input features and returns a model prediction, class probabilities, and an educational-use disclaimer |

Input validation rejects invalid values and missing required fields.

**Safety note:** Predictions are generated by a machine-learning classification model for educational demonstration only. They are not medical diagnoses or a substitute for professional healthcare advice.

### 4. Integration Testing
Integration tests were implemented in `tests/test_api.py`.

The tests cover:
1. Health endpoint and model loading.
2. Valid prediction request.
3. Invalid age validation.
4. Missing required field validation.

**Result:** 4 tests passed.

Command executed:

```powershell
python -m pytest tests/test_api.py -v
```

The test run also produced two deprecation warnings, which can be reviewed separately.

### 5. Load Testing Methodology
A load-testing script was created at `tests/load_test.py` using Python's asynchronous capabilities and HTTPX.

- Target: Local `/predict` API endpoint.
- Total requests: 50.
- Maximum concurrent requests: 50.
- Request type: POST with a consistent sample payload.
- Success criterion: HTTP 200 response.
- Measurements: Total elapsed time, response latency, throughput, and request failures.

The test was run against the locally running API. It is a small local test, not a production-scale or distributed load test.

The trained model was successfully integrated into a local FastAPI application. All four integration tests passed, and the load test completed 50 requests with no failures. Latency and throughput measurements were recorded for evaluation.

The next steps are to review dependency warnings, improve automated test coverage if required, and evaluate the application under a larger and more representative workload before any production deployment.
